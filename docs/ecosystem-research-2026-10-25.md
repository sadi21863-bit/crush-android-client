# crush-mobile ecosystem research — 2026-10-25

Research for the Kotlin/Compose Android client ("crush-mobile") embedding charmbracelet/crush v0.98.1 over `files/crush.sock` (SSE at `/v1/workspaces/{workspaceId}/events` + grant POST). Focus: does an engine upgrade fix D12 (no `permission_request` broadcast), what to borrow from similar projects, and which Kotlin libraries close our known gaps. All claims cite primary sources (GitHub source/compare APIs, release tags, official docs). Nothing was verified against a running engine here — only upstream source/releases.

## TL;DR — 5 highest-leverage adoptables

1. **crush v0.98.2 (released 2026-10-23) rewires how `permission_request` reaches remote clients** — session-scoped delivery + fail-open for clients that never report a session + republish of pending prompts, with a cross-client e2e test. Upgrading and mirroring the TUI's `POST /v1/workspaces/{id}/current-session` is the concrete path to closing D12. ([compare v0.98.1...v0.98.2](https://github.com/charmbracelet/crush/compare/v0.98.1...v0.98.2), commits `305e072`, `f1425bd`, `80374e7`).
2. **Adopt Happy's permission-decision vocabulary and handler shape** — `'approved' | 'approved_for_session' | 'denied' | 'abort'` map 1:1 onto crush's `PermissionAllow/AllowForSession/Deny` grant actions; keep a pending-map keyed by request id. ([slopus BasePermissionHandler.ts](https://github.com/slopus/happy-cli/blob/main/src/utils/BasePermissionHandler.ts), [crush internal/backend/permission.go](https://github.com/charmbracelet/crush/blob/main/internal/backend/permission.go)).
3. **cline's `ErrorRow` turn-error pattern** (typed error cards + a `retryFailedRequest` action) is the fix shape for our empty error bubbles on finish-error turns. ([ErrorRow.tsx](https://github.com/cline/cline/blob/main/apps/vscode/webview-ui/src/components/chat/ErrorRow.tsx)).
4. **java-diff-utils 4.18 (Apache-2.0, released 2026-10-18)** for the never-exercised file-diff feature; the engine already ships `metadata{diff,additions,removals}` per tool\_result, so Invoke JDU only when we must recompute diffs ourselves (e.g., undo/preview). ([release tag](https://github.com/java-diff-utils/java-diff-utils/releases), [crush proto/tools.go](https://github.com/charmbracelet/crush/blob/main/internal/proto/tools.go)).
5. **Stream durability recipe**: keep a stable UUID `client_id`, use okhttp-sse 5.5.1 with manual reconnect (no auto-reconnect), then re-list `GET /v1/workspaces/{id}/sessions/{sid}/messages` after `AttachClient` re-attach instead of relying on replay. ([okhttp-sse README](https://github.com/square/okhttp/blob/master/okhttp-sse/README.md), [crush endpoints.go registrations](https://github.com/charmbracelet/crush/blob/main/internal/server/endpoints.go), [backend.go AttachClient hold-timer comments](https://github.com/charmbracelet/crush/blob/main/internal/backend/backend.go)).

## 2) slopus/happy — mobile client for Claude Code (closest analog)

**What it is**: MIT-licensed monorepo ([LICENSE](https://github.com/slopus/happy/blob/main/LICENSE) "MIT License, Copyright (c) 2026 Happy Coder Contributors"; repo meta license = MIT, ~24.3k stars) containing React-Native/Expo mobile app (`packages/happy-app`), a **Kotlin Compose Android app in-tree** (`packages/happy-android`), the local Node sidecar (`packages/happy-cli`, npm `happy-coder`, package.json `"license": "MIT"`), the sync backend (`packages/happy-server`, `package.json` `"license": "MIT"`), and Kotlin crypto modules. Standalone `slopus/happy-cli` / `slopus/happy-server` repos have no LICENSE file (GitHub reports none) — the licenses live in the monorepo root + each `package.json`.

### Mechanisms worth adopting
- **Phone-side approve/reject of tool permissions** (our D12 use case): the CLI side exposes the SDK's `canCallTool` permission hook as `PermissionHandler` with a `pendingRequests` map (resolve/reject per request id) and a `PermissionResponse { id, approved, reason, mode, allowTools }` delivered from the phone ([happy-cli src/claude/utils/permissionHandler.ts](https://github.com/slopus/happy-cli/blob/main/src/claude/utils/permissionHandler.ts), classes/fields at lines ~21-70). A shared `BasePermissionHandler` for the Codex/Gemini agents standardizes the decision enum **`'approved' | 'approved_for_session' | 'denied' | 'abort'`** ([src/utils/BasePermissionHandler.ts](https://github.com/slopus/happy-cli/blob/main/src/utils/BasePermissionHandler.ts)) — this mirrors crush's `allow / allow_for_session / deny` exactly (verified text above), so our grant POST will already be talking the same vocabulary.
- **Permission-mode resolution precedence** (per-session mode that beats defaults, with sandbox override): a whole doc `docs/permission-resolution.md` describing app-side resolution order (in-memory session mode > persisted per-session mode > server payload > sandbox fallback), outbound message meta `meta.permissionMode`, and CLI-side startup/per-message overrides ([docs/permission-resolution.md](https://github.com/slopus/happy/blob/main/docs/permission-resolution.md)). Borrow the *idea*: persist a per-session permission mode in our app and send it with each prompt rather than a global toggle.
- **Transcript sync**: phone ↔ happy-server ↔ CLI over socket.io; server persists via Prisma/Postgres and Redis streams adapter (server package.json deps: `socket.io`, `prisma`, `ioredis`, `@socket.io/redis-streams-adapter`) ([happy-server package.json](https://github.com/slopus/happy-server/blob/main/package.json)) — we don't need the middle server (local engine + local socket), but the *client-side* sync engine pattern is reusable: their `InvalidateSync` class coalesces invalidation into a single re-running sync with backoff ([happy-cli src/utils/sync.ts](https://github.com/slopus/happy-cli/blob/main/src/utils/sync.ts)).
- **E2E encryption design** (documented, portable layouts): server stays blind; legacy `tweetnacl.secretbox` (XSalsa20-Poly1305, 24-byte nonce) or per-session/per-machine **AES-256-GCM** data key with a versioned binary layout `[version 1B | nonce 12B | ciphertext | tag 16B]` ([docs/encryption.md](https://github.com/slopus/happy/blob/main/docs/encryption.md)); a **Kotlin** implementation exists in-tree (`packages/happy-android/crypto/src/main/kotlin/com/slopus/happy/crypto/Aes256Gcm.kt`, `KeyDerivation.kt`, `Sodium.kt`, `PayloadCipher.kt` per the repo tree listing). Useful only if we later add cloud sync; over a UID-restricted local socket our needs are simpler.
- **Compose permission footer UX**: `PermissionFooter.kt` + `PermissionOptions.kt` render approve/deny choice buttons with option states; bookmark for when D12 closes ([packages/happy-android/app/src/main/kotlin/com/slopus/happy/ui/chat/PermissionFooter.kt](https://github.com/slopus/happy/blob/main/packages/happy-android/app/src/main/kotlin/com/slopus/happy/ui/chat/PermissionFooter.kt), `.../chat/tools/PermissionOptions.kt`).
- **Daemon control surface**: happy-cli's daemon exposes a small HTTP control server (`/session-started` webhook, stop, spawn, shutdown) with Zod schemas ([src/daemon/controlServer.ts](https://github.com/slopus/happy-cli/blob/main/src/daemon/controlServer.ts)) — analogous to our engine lifecycle handling; no new idea for us, but the "session reports itself" webhook is a neat pattern for our AppLog/engine status UI.
- **Files worth studying for durable reconnect + transcript fill** (paths verified via the happy-cli tree listing; content not yet reviewed — treat as reading list, not verified claims): `src/claude/utils/claudeCheckSession.ts` (+ test), `src/claude/utils/sessionScanner.ts` (+ test), `src/utils/PushableAsyncIterable.ts` (+ test), `src/utils/offlineSessionStub.ts`, and the fixture `src/claude/utils/__fixtures__/permission-prompt-aborted-with-interrupt.jsonl` documenting an interrupted permission prompt ([repo tree](https://github.com/slopus/happy-cli)).

**Verdict: ADOPT** (decision vocabulary, per-session permission mode, InvalidateSync stretch pattern). Code is MIT, so verbatim copy is fine with attribution; but its Claude-SDK shapes don't match crush's — we adapt, not import.
