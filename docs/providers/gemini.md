# Gemini API (Google Developer API) as a provider for Crush Mobile

*Researched 2026-10-17 from official Google sources only (ai.google.dev, aistudio.google.com). All URLs consulted live on that date; page "last updated" dates noted in brackets. Anything not confirmed from a live official page is marked **unverified**.*

## Summary

The Gemini Developer API is a strong candidate for a free-testing provider: a new user can get a working API key in roughly two minutes with just a Google account, and today's stable Flash models (`gemini-3.8-flash`, `gemini-3.6-flash`, `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`) are **free of charge for both input and output tokens** on the Free tier **(source: https://ai.google.dev/gemini-api/docs/pricing)**. It speaks an OpenAI-compatible REST dialect that maps onto our existing OpenCode/OpenAI-style client with only a base-URL + `Authorization: Bearer` change **(source: https://ai.google.dev/gemini-api/docs/openai)**. The two structural caveats: (1) on the free tier Google explicitly uses your prompts *and* responses to improve its products, including human review of input/output — this must be surfaced to users **(source: https://ai.google.dev/gemini-api/terms)**, and (2) the legacy 2.5 models are still priced "free" but are **access-gated to developers who used them in the past**, so a fresh user cannot rely on them **(source: https://ai.google.dev/gemini-api/docs/models)**.

## Signup

- **Flow**: Google account sign-in at Google AI Studio → accept the Gemini API Terms of Service → AI Studio "automatically creates a default Google Cloud project and API key after you accept the Terms of Service" for new users. Keys are created/copied from https://aistudio.google.com/apikey (the "Get API key" link on ai.google.dev) **(source: https://ai.google.dev/gemini-api/docs/api-key, last updated 2026-10-06)**. No waitlist is mentioned anywhere in the official docs; the only invite-gated thing is the private-preview "Contributor Tier" **(source: https://ai.google.dev/gemini-api/docs/pricing)**. Phone verification is not mentioned in the official API-key or quickstart docs — whether the interactive AI Studio UI demands it in-edge-cases is **unverified** (AI Studio is a signed-in JS app; flow could not be machine-fetched).
- **Requirements**: You must be **18+**; AI Studio may additionally require age verification on the Google Account **(source: https://ai.google.dev/gemini-api/docs/available-regions, last updated 2026-04-28; https://ai.google.dev/gemini-api/terms)**. Use is restricted to ~160 listed countries/territories (includes India, US, UK, EU, Japan, Brazil; **not** mainland China or Russia) **(source: https://ai.google.dev/gemini-api/docs/available-regions)**. Free tier is usable for developers but consumer-facing *API clients made available to users in the EEA, Switzerland, or the UK may use only Paid Services* **(source: https://ai.google.dev/gemini-api/terms)**.
- **Key type gotcha (new since 2026)**: Since **May 28, 2026, all new API keys created in AI Studio are "auth keys"** bound to a Google Cloud service account, and **the API rejects unrestricted standard keys** entirely; dormant unrestricted keys have been blocked since May 7, 2026. Fresh AI Studio users get auth keys by default, so this is invisible friction for them, but any older key a user pastes may show "Your API key was reported as leaked. Please use another API key." if Google flagged it **(source: https://ai.google.dev/gemini-api/docs/api-key; https://ai.google.dev/gemini-api/docs/troubleshooting)**.
- **There is no paid tier required to get started**; the free tier is immediate, and going paid means linking Cloud Billing plus a **minimum $5 prepay credit** **(source: https://ai.google.dev/gemini-api/docs/billing)**.

## OpenAI-compatible endpoint

- **Base URL**: `https://generativelanguage.googleapis.com/v1beta/openai/` — set this as the OpenAI client base URL and pass the Gemini key as the standard API key **(source: https://ai.google.dev/gemini-api/docs/openai, last updated 2026-10-14)**.
- **List models (picker call)**: `GET https://generativelanguage.googleapis.com/v1beta/openai/models` with `Authorization: Bearer $GEMINI_API_KEY`; single model: `GET .../openai/models/{model}` **(source: https://ai.google.dev/gemini-api/docs/openai)**.
- **Chat completions**: `POST https://generativelanguage.googleapis.com/v1beta/openai/chat/completions`, same Bearer header; `stream: true` yields SSE chunks exactly like OpenAI (`delta.content`), and `stream_options={'include_usage': true}` is supported **(source: https://ai.google.dev/gemini-api/docs/openai)**.
- **Also supported over the compat layer**: function calling (`tools`/`tool_choice`), image+audio understanding (`image_url` base64, `input_audio`), structured output (`response_format`/`parse`), embeddings endpoint, images endpoint, Sora-style `/v1/videos`, Batch API, `service_tier` (`flex`/`priority`) **(source: https://ai.google.dev/gemini-api/docs/openai)**.
- **Thinking via compat**: `reasoning_effort` maps to `thinking_level`/`thinking_budget` per model family: minimal→{Argon:low, 3.1 Flash-Lite:minimal, 3 Flash:minimal, 2.5:budget 1024}; medium→8192 (2.5); high→24576 (2.5); a nested `extra_body.google.thinking_config` passes `thinking_level`/`include_thoughts` directly; `reasoning_effort` and `thinking_*` are mutually exclusive **(source: https://ai.google.dev/gemini-api/docs/openai)**. Thought signatures for Gemini 3 are supported **(source: https://ai.google.dev/gemini-api/docs/openai)**.
- **Gemini-only features via `extra_body`**: `cached_content` and `thinking_config` on Chat; image/video (aspect_ratio, safety_settings, grounding) on their own endpoints; "Any other parameters not listed here or in the extra_body section will be **silently ignored** by the compatibility layer" **(source: https://ai.google.dev/gemini-api/docs/openai)**.
- **Documented limitations**: "Support for the OpenAI libraries is still in **beta** while we extend feature support." System-role messages appear throughout the official REST examples (supported). Safety settings and cached content are only *documented* under extra_body for Images, not Chat (chat-side safety tightening via compat is undocumented; whether it works is **unverified**) **(source: https://ai.google.dev/gemini-api/docs/openai)**.
- **Native REST alternative**: `https://generativelanguage.googleapis.com/v1beta/models/...` accepts `x-goog-api-key` header (key also accepted via query param per general Google API conventions — header shown in official examples); `/v1` and `/v1beta` both exist, preview features require `/v1beta` **(source: https://ai.google.dev/gemini-api/docs/api-key; https://ai.google.dev/gemini-api/docs/troubleshooting)**.
- **Compact error signatures we observed live on 2026-10-17** (no key sent):
  - `POST /v1beta/openai/chat/completions` (no auth) → HTTP **400**, body `[{"error":{"code":400,"message":"Missing or invalid Authorization header.","status":"INVALID_ARGUMENT"}}]` — note the error object is **wrapped in a JSON array** and uses *numeric* `code` + string `status`.
  - `GET /v1beta/openai/models` (no auth) → HTTP **404** `{"error":{"code":404,"message":"Requested entity was not found.","status":"NOT_FOUND"}}`.
  - `GET /v1beta/models` (no auth) → HTTP **403** `{"error":{"code":403,"message":"Method doesn't allow unregistered callers (callers without established identity). Please use API Key or other form of API consumer identity to call this API.","status":"PERMISSION_DENIED"}}`.

## Data-use policy (free tier) — official statement

Yes — free-tier content is used to improve Google's products, including model training ML pipeline and human review. Verbatim from the **Gemini API Additional Terms of Service** (effective March 23, 2026):

> "When you use Unpaid Services, including, for example, Google AI Studio and the unpaid quota on Gemini API, Google uses the content you submit to the Services and any generated responses to provide, improve, and develop Google products and services and machine learning technologies, including Google's enterprise features, products, and services, consistent with our Privacy Policy. To help with quality and improve our products, **human reviewers may read, annotate, and process your API input and output.** ... **Do not submit sensitive, confidential, or personal information to the Unpaid Services.**"

**(source: https://ai.google.dev/gemini-api/terms, last updated 2026-04-28)**

The pricing page's headline table states it tersely: Free tier = "Content used to improve our products*"; Paid = "Content not used to improve our products*" **(source: https://ai.google.dev/gemini-api/docs/pricing)**. For Paid Services, Google "doesn't use your prompts ... or responses to improve our products" and logs only for abuse detection **(source: https://ai.google.dev/gemini-api/terms)**. Exception: users in the **EEA, Switzerland, or UK** get the paid-tier data protections even on free quota ("the terms under 'How Google uses Your Data' in 'Paid Services' apply to all Services ... including unpaid quota in the Gemini API") **(source: https://ai.google.dev/gemini-api/terms)**. For Crush Mobile users: whatever they chat on a free Gemini key is potentially read by Google reviewers — a UI disclosure is warranted.

## Gotchas

1. **2.5 models are gated**: pricing still lists `gemini-2.5-flash`/`flash-lite`/`pro` as free, but the models page says access is limited to developers who actively used them in the past; new projects are told to use `gemini-3.5-flash-lite` or `gemini-3.8-flash`. A fresh user's key should target 3.x models **(source: https://ai.google.dev/gemini-api/docs/models)**.
2. **Deprecation timelines are aggressive**: `gemini-3.1-flash-lite` shutdown **May 7, 2027** (replacement: `gemini-3.5-flash-lite`); `gemini-3-flash-preview`/`gemini-3.6-flash` are unofficially termed "legacy"; `gemini-2.0-flash`/`flash-lite` shut down June 1, 2026; `gemini-3-pro-preview` shut down March 9, 2026. Preview models get only "at least 2 weeks notice". There is a `latest` alias (e.g. `gemini-flash-latest`) that hot-swaps with replacements (2-week email notice before swaps) — good as a picker default, risky as a stable id — and Aliases/pinning must be user-visible **(source: https://ai.google.dev/gemini-api/docs/deprecations; https://ai.google.dev/gemini-api/docs/models)**.
3. **Thinking budgets / levels (ThinkingConfig)**: Gemini models think **by default**, and "Reasoning cannot be turned off for Gemini 2.5 Pro or 3 models" (compat doc). Per-model supported levels: `gemini-4-argon`/`gemini-3.8-flash`: default medium, levels low/medium/high — and for `gemini-3.8-flash` "**minimal is not supported and returns an error**"; `gemini-3.6-flash`/`gemini-3.5-flash-lite`/`gemini-3-flash-preview`: minimal–high; `gemini-2.5-flash-lite`: default Off; 2.5 models used numeric budgets (1024–24576 via compat mapping) **(source: https://ai.google.dev/gemini-api/docs/thinking; https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash; https://ai.google.dev/gemini-api/docs/openai)**. So sending `reasoning_effort: "minimal"`/`"none"` at 3.x models can 400 — our provider adapter should clamp per model.
4. **Sampling params are deprecated on new models**: "Gemini 4 and Gemini 3.6+ models ignore custom values for `temperature`, `top_p`, and `top_k` and return deprecation warning headers (and will return `400` errors in a future release)." Valid ranges while they do apply: temperature 0.0–1.0, topP 0.0–1.0, candidateCount 1–8 **(source: https://ai.google.dev/gemini-api/docs/troubleshooting)**.
5. **Safety settings**: adjustable category thresholds (`harassment`, `hate_speech`, etc.); default is effectively **Off for Gemini 2.5+ models**. When something is blocked you get HTTP **400** with code `safety` (`jailbreak`, `prohibited_content`, `blocklist`, `recitation`, `spii`, `image_safety`...) and the stream carries an error event instead of a partial answer **(source: https://ai.google.dev/gemini-api/docs/safety-settings, last updated 2026-10; https://ai.google.dev/gemini-api/docs/api-errors)**. Apps with less restrictive safety settings "may be subject to Google's review and approval" **(source: https://ai.google.dev/gemini-api/terms)**.
6. **Code execution**: supported at model level on the current Flash models (e.g. `gemini-3.8-flash` "Code execution: Supported") but it is **not listed** in the compat extra_body table — treat code-execution-through-OpenAI-compat as **unverified/undocumented**; grounding via `google_search` tool is only documented under compat for the Images endpoint, "only available on Gemini 3 and newer models" **(source: https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash; https://ai.google.dev/gemini-api/docs/openai)**.
7. **Context caching**: implicit caching is on by default for all Gemini 2.5+ models with min prompt sizes (4,096 tokens for 3.x/4, 2,048 for 2.5) and savings pass through; explicit caching is NOT supported for Gemini 4 Argon and onward (use `generateContent` API for 3.x/2.5 explicit caches); compat exposes `extra_body.google.cached_content` for Chat **(source: https://ai.google.dev/gemini-api/docs/caching, last updated 2026-10-13; https://ai.google.dev/gemini-api/docs/openai)**.
8. **Leak/dormant-key enforcement**: Google actively blocks leaked keys with the error "Your API key was reported as leaked. Please use another API key." — together with the auth-key transition, client-side key hygiene matters (Google officially recommends a backend proxy for client-side apps; our users pass keys into the local on-device server instead) **(source: https://ai.google.dev/gemini-api/docs/troubleshooting; https://ai.google.dev/gemini-api/docs/api-key)**.

## Rate limits and errors

- **Dimensions**: RPM, TPM (input tokens), RPD; some models have IPM/TPD variants; exceeding **any one** triggers a 429 even if the others have headroom **(source: https://ai.google.dev/gemini-api/docs/rate-limits)**.
- **Scope and reset**: enforced **per project, not per API key**; RPD resets at **midnight Pacific time**; preview/experimental models are more restricted; per-model live numbers are shown in AI Studio (https://aistudio.google.com/rate-limit) rather than published **(source: https://ai.google.dev/gemini-api/docs/rate-limits)**.
- **Usage tiers**: Free (active project) → Tier 1 (link billing; $250 billing cap) → Tier 2 ($100 spend + 3 days; $2,000 cap) → Tier 3 ($1,000 + 30 days; $20k–$100k+). Spend-based per-10-minute limits: Free N/A, Tier 1 $10, Tier 2 $50, Tier 3 $200 **(source: https://ai.google.dev/gemini-api/docs/rate-limits)**.
- **429 error signatures**: Three distinct 429 codes exist — `rate_limit_exceeded` (per-minute/second request-token limit), `quota_exceeded` (daily quota), `too_many_requests` (short-window burst); the classic gRPC-JSON shape `{"error":{"code":429,"status":"RESOURCE_EXHAUSTED","message": ...}}` is what the rate-limits page itself cites for spend-limit hits; a request that "exceeded your daily quota" should be retried only after reset, not backoff-looped **(source: https://ai.google.dev/gemini-api/docs/api-errors, last updated 2026-09-20; https://ai.google.dev/gemini-api/docs/rate-limits)**.
- **Retry guidance (official)**: exponential backoff with **jitter**; the official Python SDK retries transient errors up to **4 times, ~1 s initial delay, 60 s max delay**; retry only on 429/408/5xx; **do not retry 400/402/403** (key problems, depleted prepay credits, bad syntax); 402 `payment_required` = prepay balance depleted, never retry until credits added **(source: https://ai.google.dev/gemini-api/docs/troubleshooting; https://ai.google.dev/gemini-api/docs/api-errors)**. SSE requests surface failures as `event_type: "error"` events on the stream, so our streaming client must watch for error events, not just non-200 status **(source: https://ai.google.dev/gemini-api/docs/api-errors)**.

## Verdict for Crush Mobile

A new user *can* realistically get a $0 key today: they need only a personal Google account (18+, region on the ~160-country list), one ToS acceptance at https://aistudio.google.com, and AI Studio auto-provisions the default Cloud project and (auth-type) API key instantly — no waitlist, no credit card, no prepay for the free tier. With that key they can chat for free on `gemini-3.8-flash` (and `gemini-3.6-flash` / `gemini-3.5-flash-lite` / `gemini-3.1-flash-lite`) through the OpenAI-compatible base `https://generativelanguage.googleapis.com/v1beta/openai/`, including streaming, function calling, multimodal input, and a real model-picker endpoint, with 1M-token context and thinking on the current models — genuinely the lowest-friction $0 path we have evaluated. The honest strings attached: exact free RPM/RPD numbers are no longer published publicly (per-key quota after first sign-in, RPD resets midnight PT), the 2.5 models are off-limits to fresh users despite still showing "free", `gemini-3.1-flash-lite` dies May 7 2027 so our picker must not hard-code it, `reasoning_effort:"minimal"` 400s on some Flash models, and - critically - free-tier prompts/outputs are used by Google to improve its products with human review, so we must disclose that in the provider's consent UI (or position Gemini as the "no-privacy, zero-cost" testing provider vs. paid tiers, which require a $5 prepay to even start).
