## 3. The compatibility adapter (step 1 — the code work)

**IMPLEMENTED IN CODE 2026-11-12 (pending the device rails).** One seam
(`EngineProtocol`) decides the wire shape from the **engine version observed
at bind** (never from a build-time assumption, so a rollback binary still
speaks its own protocol):

- `version >= 0.100.0` → create with `permission_mode` enum; re-apply via
  `POST …/permissions/mode`.
- older (or an unparseable/absent version — fail safe) → the current `yolo`
  bool + `…/permissions/skip`.
- **Fail closed on a protocol surprise**: a claimed version whose endpoint
  answers 404/400 (or an unparseable version) logs an honest line and stops
  the attach path that would set an unknown permission posture — never "carry
  on and hope". (The rails are the proof point: the adapter's v0.100 half has
  no device evidence until step 4 runs.)

Tests: pure mapping rows (each `PermissionMode` → exact wire value per version
family, version parsing including `v` prefixes and `+dirty` suffixes) + a
contract test that the adapter declares BOTH families supported while the
rails-proven row stays the pinned version (the manifests and the adapter can
never drift apart silently).

Product decision (owner, step 5): Sysadmin Mode is **not** surfaced in v1 of
this upgrade. Chat stays deny-all; Code keeps the existing ASK default. The
`sysadmin` enum value exists in the wire type but is unreachable from the UI
(`EngineProtocol.modeFor` cannot produce it).

## 5. Risks and watch items (honest, one line each)

- **Enum spelling** (`normal|yolo|sysadmin`) is the 400-risk on create/apply —
  verify via the engine's own readback before trusting a green attach.
- **Permission family on re-attach** (the first v0.100.0 T3 failure): making
  `open()` version-aware is not enough — the stored wire must ride every
  `reattachIfStale()`, and the unknown-version fail-safe must follow
  `PINNED_VERSION`. Guarded by rail 1b + `BootstrapOrderTest`.
- **Session data compatibility** is unclaimed by the vendor — the rollback
  drill (rail 9) decides whether v0.99 can reopen v0.100 data; if not, the
  rollback note must say so.
- **Sub-agent SSE parts** must degrade to text; the `observed tool_call
  shape` lines are the canary (the renderer must never crash on a new part).
- **Stale tool advertisement** (S-01 residual, upstream): re-run the
  fresh-advertisement probe on this binary; record the observed state even if
  unchanged.
- **Beam Free (#4222)**: retest as the model-side acceptance item; if still
  open upstream, the picker gate stays.
- **crushrc marker semantics**: re-measure, record the truth (§1 last bullet).
- **Free-model flake family**: unchanged by this upgrade; retry discipline
  stays.

## 6. Rollback

Revert the binary + `PINNED_VERSION` (manifest rows are additive and stay).
Keep the previous APK on hand. Device data dirs are preserved untouched; the
rollback drill's result is the authoritative statement on data compatibility.

## 7. What "done" looks like

T0–T2 green in CI, T3 scripted rails green on device, the interactive rails
green with DB evidence folded, `PINNED_VERSION = "0.100.0"`, and the status
hub carrying the chain row. Nothing before that changes the shipped engine.
